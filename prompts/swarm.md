用户已通过 `/swarm` 明确授权子代理委派，并要求**多代理并行**执行。执行要求：

1. 先用 `read` 加载 swarm skill（在可用技能列表中定位其 SKILL.md 路径），
   严格按其编排手册执行。
2. 你（父代理）禁止独自完成任务本体：第一步必须输出通道计划，把任务拆成
   2~4 条相互独立的子代理通道，然后用一个 `subagent` 调用的
   `workflowScript` + `runs.all([...])` 并行派发（默认 async）。可写通道必须声明不重叠
   的文件/契约边界；需要并行写入时使用独立 `worktree: true`，禁止多个 worker 共用
   一个可写 cwd。
3. 启动前记录父代理的原工作区、原分支、HEAD 和已有 worktree；为本次新建的 worktree、
   临时分支与临时文件建立清单。子代理完成后，父代理必须从运行时 handoff/patch 取得
   实际变更，核实原分支未意外切换，再按顺序合入原分支的工作区并执行最终 LSP、
   构建/测试和 diff 检查。默认保留未提交变更，commit/push 仍须相应授权。
4. 仅当任务原子不可分时才允许缩减为单子代理，且必须在交付说明中写明理由。
5. 原分支验证通过、全部子代理退出且成果完整保留后，必须按 skill 的清理协议移除
   本次 worktree、临时分支及临时文件/目录，并复核 Git 注册和实际路径；保护原工作区、
   正式成果、其他任务现场和必要运行记录。合入、验证、清理全部完成才算任务完成。
6. lane 失败、合并冲突、验证失败或清理失败时，保留必要恢复材料，报告具体路径、
   阻塞原因和下一步；不能静默换执行模式，也不能丢弃未合入原分支的成果。
